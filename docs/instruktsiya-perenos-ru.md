## 0. Три правила безопасности — прочитать обязательно

1. **На старом сервере ничего не удалять и не менять.** Только смотреть и копировать. Старый сайт должен работать до самого дня переключения.
2. **Пароли никому не пересылать** — ни в Telegram, ни в WhatsApp, ни Некрузу, ни Claude. В отчёте пишите «пароль найден / есть доступ», а сам пароль храните у себя.
3. **Персональные данные пользователей** (ФИО, паспорт, телефоны) из базы старого сайта **не выкладывать в интернет и не пересылать** в мессенджерах. Копию базы целиком переносим только напрямую со старого сервера на новый (шаг 2.6). Наружу отправляем только структуру базы и публичные данные (акты, планы, проекты).

## Этап 2. Старый сервер: доступ, сведения, резервная копия

### 2.1. Узнать адрес старого сервера (на своём компьютере с Windows)

1. Нажмите **Пуск**, наберите `cmd`, нажмите **Enter** — откроется чёрное окно «Командная строка».
2. Введите по очереди (после каждой строки — **Enter**):
   ```
   nslookup www.portali-huquqi.tj
   nslookup -type=NS portali-huquqi.tj
   ```
3. Сфотографируйте или скопируйте результат. Первая команда покажет **IP-адрес сервера** (строка `Address:` в ответе на портал, не первая строка с адресом вашего DNS). Вторая покажет, **кто обслуживает DNS домена** (строки `nameserver =`). Это нужно для этапов 4 и 6.

### 2.2. Получить доступ к серверу

Попросите у администратора старого сервера **один** из вариантов (лучше первый):
- **SSH-доступ** (адрес, логин, пароль или ключ). Права: чтение файлов сайта + возможность выполнить `mysqldump`.
- Если SSH не дают — доступ к **панели хостинга** (cPanel, ISPmanager, Plesk и т. п.) с **phpMyAdmin**.
- Если не дают ничего — попросите администратора **самого** выполнить шаги 2.3–2.6 и отдать вам файлы.

### 2.3. Подключиться по SSH (Windows 10/11, ничего устанавливать не нужно)

1. **Пуск** → наберите `PowerShell` → **Enter**.
2. Введите (вместо `ЛОГИН` и `IP` — ваши данные):
   ```
   ssh ЛОГИН@IP
   ```
3. На вопрос `Are you sure you want to continue connecting (yes/no)?` напишите `yes` → **Enter**.
4. Введите пароль (при вводе символы **не отображаются** — это нормально) → **Enter**.
5. Появится строка вида `ЛОГИН@имя-сервера:~$` — вы на сервере.

Для перетаскивания файлов мышкой установите **WinSCP** (https://winscp.net, кнопка Download): **Новое подключение → Протокол файла: SFTP → Имя хоста: IP → Имя пользователя → Пароль → Войти**. Слева ваш компьютер, справа сервер.

### 2.4. Собрать сведения о сервере (только чтение, ничего не меняет)

Скопируйте этот блок целиком, вставьте в окно SSH (правая кнопка мыши = вставить) и нажмите **Enter**. Он создаст файл с отчётом:

```bash
mkdir -p ~/portal-export && cd ~/portal-export
{
echo "== СИСТЕМА"; lsb_release -a 2>/dev/null; uname -a; uptime
echo "== ДИСК"; df -h
echo "== ПАМЯТЬ"; free -h
echo "== ПО"; apache2 -v 2>/dev/null; php -v 2>/dev/null | head -1; mysql --version 2>/dev/null; psql --version 2>/dev/null
echo "== САЙТЫ APACHE"; ls -la /etc/apache2/sites-enabled/ 2>/dev/null
grep -RhiE "ServerName|ServerAlias|DocumentRoot" /etc/apache2/sites-enabled/ 2>/dev/null
echo "== ПАПКИ САЙТА"; ls -la /var/www/ /var/www/html/ 2>/dev/null
echo "== РАЗМЕР ПАПОК"; du -sh /var/www/* /var/www/html/* 2>/dev/null
echo "== НАСТРОЙКИ PHPMAKER (без паролей)"
for f in $(find /var/www -maxdepth 4 -name 'ewcfg*.php' 2>/dev/null); do
  echo "-- $f"; grep -E "type|host|[\"']db[\"']|port|UPLOAD_DEST_PATH" "$f" \
    | perl -pe 's/(["\x27]pass["\x27]\s*=>\s*)(["\x27])(?:\\.|(?!\2).)*\2/$1"***"/g'
done
echo "== CRON"; crontab -l 2>/dev/null; ls /etc/cron.d/ 2>/dev/null
} > server-report.txt 2>&1
cat server-report.txt
```

**Отправьте Некрузу файл `server-report.txt`** (в нём нет паролей). Скачать его можно через WinSCP из папки `/home/ЛОГИН/portal-export/`.

Из отчёта мы узнаем: тип базы данных (`"type"` — например `MYSQL`), имя базы (`"db"`), где лежат загруженные файлы (`UPLOAD_DEST_PATH`), и есть ли кроме публичных частей (`publicria`, `publicadliya`) ещё и административная часть (через неё министерства вносят планы и проекты).

### 2.5. Структура базы данных (если в отчёте `"type" => "MYSQL"`)

Логин и пароль базы — в файле `ewcfg14.php` (путь показан в отчёте), строки `"user"` и `"pass"`. Посмотреть их можно так (выведет на экран только вам):
```bash
grep -E '"user"|"pass"' /var/www/ПУТЬ/ewcfg14.php
```

Дальше вместо `ПОЛЬЗОВАТЕЛЬ` подставьте значение `"user"`; пароль система спросит сама (`Enter password:`).

```bash
cd ~/portal-export
# 1) список баз и их размер
mysql -u ПОЛЬЗОВАТЕЛЬ -p -e "SELECT table_schema AS db, ROUND(SUM(data_length+index_length)/1024/1024) AS mb, DEFAULT_CHARACTER_SET_NAME AS charset FROM information_schema.tables JOIN information_schema.schemata ON schema_name=table_schema GROUP BY table_schema, charset;" > databases.txt
cat databases.txt
```

Для **каждой** базы из списка, кроме системных (`information_schema`, `mysql`, `performance_schema`, `sys`), выполните (вместо `ИМЯ_БАЗЫ` — имя):

```bash
# 2) список таблиц с количеством строк
mysql -u ПОЛЬЗОВАТЕЛЬ -p -e "SELECT table_name, table_type, table_rows FROM information_schema.tables WHERE table_schema='ИМЯ_БАЗЫ' ORDER BY table_name;" > tables_ИМЯ_БАЗЫ.txt
# 3) только структура, без данных (безопасно пересылать)
mysqldump -u ПОЛЬЗОВАТЕЛЬ -p --no-data --routines --triggers ИМЯ_БАЗЫ > schema_ИМЯ_БАЗЫ.sql
```

**Отправьте Некрузу:** `databases.txt`, все `tables_*.txt`, все `schema_*.sql`. По ним я напишу программу переноса и скажу, какие именно таблицы с публичными данными нужно выгрузить отдельно.

*Если тип базы не MySQL (например MSSQL или PostgreSQL) — остановитесь и пришлите отчёт, я дам другие команды.*

*Если доступ только через phpMyAdmin:* слева выберите базу → вкладка **Экспорт** → способ **Обычный** → в разделе «Вывод данных» отметьте **только структура** → формат **SQL** → **Вперёд**. Это заменяет пункт 3.

### 2.6. Полная резервная копия (хранится только на сервере, никуда не пересылается)

```bash
cd ~/portal-export
# база целиком (для каждой базы); --single-transaction не блокирует работающий сайт
mysqldump -u ПОЛЬЗОВАТЕЛЬ -p --single-transaction --quick --routines --triggers --hex-blob --default-character-set=utf8mb4 ИМЯ_БАЗЫ | gzip > full_ИМЯ_БАЗЫ_$(date +%F).sql.gz
# файлы сайта целиком (код + загруженные PDF)
sudo tar czf www_$(date +%F).tar.gz /var/www
# контрольные суммы, чтобы проверить, что копия не повредилась при переносе
sha256sum *.gz > checksums.txt
ls -lh
```

Пришлите Некрузу **только** вывод команды `ls -lh` (размеры файлов) и `checksums.txt`. Сами архивы позже перенесём напрямую на новый сервер (этап 5).

*Через phpMyAdmin:* вкладка **Экспорт** → **Обычный** → формат **SQL** → «Сжатие: gzip» → **Вперёд**. Файл сохраните на флешку/зашифрованный диск, не в мессенджер.

## Этап 3. Новый сервер

### 3.1. Какой сервер нужен

- **Где:** в Таджикистане (уточнить в этапе 1, где обязаны стоять государственные сайты — возможно, у ММҚ/Минюста уже есть свой дата-центр или договор).
- **Система:** Ubuntu Server **24.04 LTS** (64-бит).
- **Минимум:** 2 процессора, 4 ГБ памяти, 80 ГБ SSD. Публичный IP-адрес.
- **Открытые порты:** 22 (SSH, лучше только для своих адресов), 80 и 443 (сайт).
- Доступ **root** или пользователь с `sudo`.

### 3.2. Первичная настройка (один раз)

Подключитесь: `ssh root@НОВЫЙ_IP` (как в шаге 2.3). Вставьте блок целиком:

```bash
apt update && apt -y upgrade
timedatectl set-timezone Asia/Dushanbe
adduser --gecos "" portal            # спросит пароль для нового пользователя — придумайте и сохраните
usermod -aG sudo portal
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
curl -fsSL https://get.docker.com | sh
usermod -aG docker portal
mkdir -p /opt/portal && chown portal:portal /opt/portal
echo "ГОТОВО"
```

Отключитесь (`exit`) и зайдите уже как `portal`: `ssh portal@НОВЫЙ_IP`.

### 3.3. Доступ сервера к коду на GitHub (ключ только для чтения)

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519 -C "portal-server"
cat ~/.ssh/id_ed25519.pub
```

Скопируйте строку, которая начинается с `ssh-ed25519`, и отправьте Некрузу. Это **не секрет** — это открытый ключ.

*Для Некруза:* GitHub → репозиторий **portali-huquqi** → **Settings** → **Deploy keys** → **Add deploy key** → Title: `portal-server` → вставить ключ → галочку **Allow write access НЕ ставить** → **Add key**.

### 3.4. Скачать и запустить новую версию

После того как Некруз добавил ключ:

```bash
cd /opt/portal
git clone git@github.com:Nekruzzz/portali-huquqi.git .
git checkout claude/hopeful-einstein-46fo17     # рабочая ветка, пока изменения не перенесены в main
cd portali-huquqi
cp .env.example .env
openssl rand -hex 32                             # скопируйте результат — это SECRET_KEY
nano .env
```

В редакторе `nano` (стрелки — перемещение, **Ctrl+O → Enter** — сохранить, **Ctrl+X** — выйти) заполните:

| Строка | Значение сейчас |
|---|---|
| `SITE_ADDRESS=` | `:80` |
| `COOKIE_SECURE=` | `0` |
| `BASE_URL=` | `http://НОВЫЙ_IP` |
| `SECRET_KEY=` | строка из `openssl rand -hex 32` |

Запуск (первый раз 3–5 минут):
```bash
docker compose up -d --build
docker compose ps
```
У трёх строк (`app`, `scheduler`, `caddy`) в колонке STATUS должно быть **Up**.

Создать администратора (спросит пароль два раза):
```bash
docker compose exec app flask --app app create-admin ВАШ_EMAIL
```

**Проверка:** откройте в браузере `http://НОВЫЙ_IP` → должна открыться главная страница портала (пока пустая — данных ещё нет). Нажмите **Ворид шудан**, войдите с e-mail и паролем администратора → должна открыться панель **Идоракунӣ**.

### 3.5. Ежедневная резервная копия

```bash
cd /opt/portal/portali-huquqi
./backup.sh                 # проверка: в конце должна быть строка "ok backups/portal_....tar.gz"
crontab -e                  # если спросит редактор — выберите 1 (nano)
```
В конец файла добавьте строку, сохраните (**Ctrl+O → Enter → Ctrl+X**):
```
30 2 * * * cd /opt/portal/portali-huquqi && ./backup.sh >> backups/backup.log 2>&1
```
Каждую ночь в 02:30 будет копия, хранятся 14 последних. Раз в неделю скачивайте папку `backups` через WinSCP на другой носитель.

## Этап 4. Тестовый адрес с HTTPS: new.portali-huquqi.tj

Нужен тот, у кого есть доступ к **DNS домена** portali-huquqi.tj (кто именно — видно из шага 2.1, строки `nameserver`; уточнить в Минюсте/ММҚ).

1. В панели DNS добавить запись: **Тип:** `A`, **Имя:** `new`, **Значение:** `НОВЫЙ_IP`, **TTL:** `300`.
2. Проверить через 10–30 минут на своём компьютере: `nslookup new.portali-huquqi.tj` → должен показать новый IP.
3. На новом сервере `nano .env` и поменять:
   ```
   SITE_ADDRESS=new.portali-huquqi.tj
   COOKIE_SECURE=1
   BASE_URL=https://new.portali-huquqi.tj
   ```
4. `docker compose up -d` → через минуту откройте `https://new.portali-huquqi.tj` — должен быть замок в адресной строке. Сертификат выпускается и продлевается автоматически (Let's Encrypt). *Если по правилам нужен другой сертификат — сообщите (вопрос Б6).*

## Этап 6. Переключение (будет уточнён)

Коротко: за сутки снизить TTL записей домена до 300 → в согласованное время остановить внесение изменений на старом сайте → последний импорт → поменять запись `A` для `portali-huquqi.tj` и `www` на новый IP → поменять `SITE_ADDRESS` → проверка. Старый сайт остаётся на старом сервере под адресом `old.portali-huquqi.tj` (только чтение) 3–6 месяцев.
